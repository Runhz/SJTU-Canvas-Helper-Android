# 0.1.1 双认证与连接诊断

2026-10-15（台北时间）。只连接交大本部，保留同一手机完成登录的要求。

## 本次调整

- 第一步验证 Canvas Token，第二步完成 jAccount 额外认证。扫码与官方网页登录是第二步的两种入口。
- 复用 Windows 版的 `get_uuid`、jAccount WebSocket `UPDATE_QR_CODE`／`LOGIN` 及 `express_login` 协议。二维码会话绑定账号并设有效期；取消或切换账号后不接受旧会话。
- 同机扫码：保存二维码到相册，打开微信扫一扫，从相册识别并确认，返回应用后回查。也可尝试本机官方确认页。远程网页登录页没有应用业务桥，密码和验证码由用户在官方页面填写。
- 回查取得凭据后再核验 jAccount、Canvas 网页、旧录播会话和云盘，分别显示状态。未扫码确认不算认证成功。
- 手机粘贴 Token 时清理空白、换行、不可见字符与 Bearer 前缀；拒绝包含说明文字的输入。前后端均验证，令牌不加入源码或日志。
- Token 验证设置 18 秒超时，区分 401、403、网络、超时和解析错误。新增不携带 Token 的系统 HTTPS 网络自检。
- 课程同步异步显示进度，认证完成后立即返回可操作界面；单门课程失败时保留该课程上次结果，并提示列表不完整。
- 修复 Chromium 74 缺少 `Promise.allSettled` 导致同步中断的问题，使用兼容实现；补上旧 WebView 的弹窗高度与定位回退。
