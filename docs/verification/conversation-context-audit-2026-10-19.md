# 对话恢复与资料上下文边界检查

2026-10-19，接续同日的 PDF 读取结果复用修复。仅修改本地源码，没有重新打包 APK、改动版本号、提交或上传 GitHub。公开及本地 0.8.7 APK 均不包含本轮修复。

## 确认的问题与修复

| 问题 | 修复与验证 |
| --- | --- |
| 输入草稿后很快换文件，500ms 延迟保存可能读到新对话，旧草稿丢失 | 切入口前同步提交旧对话快照；未完成恢复的占位对话不提前保存。UI 回归测试覆盖快速换文件 |
| 点击新对话，sourceJob 仍优先选中旧对话 | 显式 newChat 跳过旧运行任务及存储记录；新草稿使用新的会话 ID |
| 显式 conversationId 已失效，自动回退到同来源的其他对话 | 显式 ID 不做同来源回退；打开新对话并说明原记录不可用，不自动发送入口问题 |
| 内存旧任务比本机新草稿更早，却抢先恢复 | 同来源比较更新时间，同 ID 运行状态仍以实时任务为准 |
| 删除对话后，延迟保存或界面切换再次写入旧 ID | 会话内删除标记阻止旧 ID 保存和提问；清除任务延迟计时器；存储删除失败时撤销标记，允许继续编辑 |
| 双栏中另一栏仍显示已删除对话，后台任务继续 | 删除完成后发送按账号和会话 ID 限定的事件；其他栏清空该对话显示并进入新对话，取消关联任务，刷新历史列表 |
| 失败重试后，同一 messageIndex 留下两个资料定位 | 重试替换该问题的失败定位；恢复旧记录时同一位置保留最后一个有效定位 |
| 资料甲读取完成时，用户已选资料乙，甲结果覆盖乙的缓存 | 为原问题保留甲的请求资料；当前资料选择按实际现状合并，只恢复匹配的文件，不覆盖乙及新草稿。停止准备后不启动模型请求 |
| 用户取消截图，下一次请求仍隐式回填旧截图 | 资料面板及输入框移除图片时记录明确排除意图；保留该意图至持久化；自动沿用旧图必须匹配同一来源、时间及文件选择 |
| 旧记录中的损坏思考字段、空定位或重复定位导致界面异常 | 恢复时保留有效问答，清理损坏元数据；规范化追问、符号、阅读方式及问题定位 |

这些修复没有将模型服务改为永久文件存储，没有修改 PDF 解析或视觉识别精度，也没有引入新依赖或数据库结构迁移。

## 证据

- 修改前先增加回归测试：`context-audit-before.json` 出现 6 项失败，分别暴露草稿丢失、新对话复用、缺失 ID 串会话、删除后复活及重试定位重复。
- `context-audit-images-before.json` 出现 1 项失败：明确排除旧图后仍把旧截图送入模型请求。
- `context-audit-legacy-before.json` 出现 1 项失败：旧记录损坏元数据未清理。
- 最终完整前端测试 253 项通过、失败 0，报告 `local-diagnostics/context-audit-final.json`。本轮新增 14 项测试，包含双栏删除、删除失败回滚、延迟准备与取消、最近草稿恢复。
- 类型检查、生产构建、180 份前端源文件编码及中文 JSON 往返检查通过。
- 632 份公开候选文件通过 UTF-8 与基本凭据/密钥检查；本轮修改通过 `git diff --check`。

测试使用本机浏览器测试环境、IndexedDB 替身和受控模型/文件读取接口。没有使用真实模型服务、真实 Canvas 课件或物理设备进行本轮验收；未实测系统强杀、磁盘满和系统清理 WebView 数据。系统强杀发生在持久化完成前，最后一段内容仍可能丢失，不能声称彻底消除所有退出丢失问题。

## 维护定位

- `demo/src/AiChat.tsx`：入口恢复、草稿提交、新对话和双栏删除响应。

- `demo/src/studyAttachments.ts`：用户明确选择哪些图片、文字和文件。
