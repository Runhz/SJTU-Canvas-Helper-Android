# 0.5.0 实施计划：界面重构、缓存与学习助手

依据：用户本轮七张手机截图与反馈，含后续确认的“圆形透明水缸、高分辨率、强调晃动与丰满程度”。本轮先完成这一版，不重复沿用旧卡片和系统下拉框。

## 已定位的问题

1. 课程卡片顶栏的通用 span 规则同时覆盖图标容器与课程代码。代码又预留菜单宽度，长课程名／代码被挤压；图标的网格居中被 flex 规则覆盖。需改为明确的图标、标题、辅助信息、底部操作结构。
2. 学期、课程、模型等直接使用 select，安卓弹出旧式系统单选框，与应用风格分离。
3. `loadDashboard` 每次重取所有课程，并对所有历史课程遍历作业；启动后先联网验证再恢复缓存。课程元数据不持久化，文件列表仅保留在内存，因此出现反复从零同步和长时间等待。
4. 播放器是位于 WebView 上方的原生浮层，滚动坐标经异步桥更新；其矩形视频表面和原生 Button 行造成方边、滚动延迟及风格断裂。字幕没有跟随播放位置。
5. AI 读取预算由用户手工配置，模型列表只提取名称，没有能力元数据；全局助手缺少明确的跨课程按需读资料通道，截图提问尚未实现。

## 设计与交互决定

- 手机、Pad 共用一套组件与布局规则。中性浅色／深色底、清晰正文、克制强调色；不再使用随机课程图形和拥挤的卡片代码列。
- 顶部保留品牌及必要操作，删除“本部”标签和连接／同步进度条。后台更新只在当前内容需要反馈时显示轻量状态，手动刷新仍可用。
- 首页按时间变化：日期、时段、最近截止、今日日程；作业完成视觉使用透明圆形水缸，数字明确显示已提交／总数。
- 课程标题完整换行，手机两列在宽度不足时改为一列；管理按钮放入底部操作区，长按仍可管理。录播先展示课程卡片，点击后展示该课程录播，不再先弹课程选择框。
- 学期／模型等选择用统一可搜索底部面板。所有图标固定 viewBox、宽高和居中；交互元素至少有足够触控范围。
- 卡片按压、抬起、选中、列表更新、弹窗、播放状态和水位变化采用连贯的短动画；只对正在交互的区域使用呼吸／涟漪，避免整页不停闪动。遵从减少动态效果设置。
- 全面删去口号、无意义提示和面向开发者的解释。无字幕仅写“平台未返回可用字幕”。保留必要的真实提交确认、费用／网络错误和资料覆盖范围提示。

## 阶段与完成标准

### A. 统一界面组件

新增明确的课程卡片、选择面板与一致的按钮／图标规范，重构首页、课程、录播和“我的”；新增底部“助手”入口。简化品牌图标并同步 Android 启动图标。完成长中文课程名、长代码、空数据、夜间模式及手机／Pad布局检查。

### B. 缓存与按需刷新

- 按账号保存课程元数据、作业快照、资料目录、录播列表和资料元数据，启动先读缓存并显示，再恢复会话。
- 课程元数据缓存约 15 分钟；当前学期作业按课程约 3 分钟；课程文件、录播列表约 10 分钟；字幕／切片约 1 小时。首次、过期和手动刷新分别处理，正在进行的同资源请求合并。
- 普通后台刷新只检查当前范围内需要刷新的课程。切换课程／资料时先显示已有目录，再按过期时间更新；不预下载全部原文件，不提前送给模型。
- 手动刷新强制检查当前页面的数据；无变化时保留原对象／列表，有变化时按资源 ID 合并，保留用户的置顶、忽略、滚动与选择。
- 失败保留缓存并允许重试；账号切换隔离在途请求和缓存。没有服务器增量接口时使用资源级 TTL 与可用的条件请求，不伪造增量查询参数。

### C. 高清透明水缸

已找到 ECharts LiquidFill 与 React Liquid Gauge，但其平面水波视觉不足以满足本次高品质透明水缸要求。优先用成熟 Three.js 渲染能力验证透明缸、折射／反射、水面高光与惯性水波；不将普通进度条包装成真实流体模拟。

- 圆形透明缸，水的体积／水位随完成比例平滑变化；下方独立显示完成数量，不依赖水位读数。
- 使用设备方向／重力与加速度驱动倾斜和衰减波动，不涉及地理位置；触摸也能产生轻微水波。Pad 同样可用。
- 画质优先，按实际像素比渲染；模块延迟加载，离屏／后台暂停。无传感器、WebGL不可用或减少动态效果时提供可用降级。
- 设置增加“水缸画质”手动选择：省电 30 帧／均衡 45 帧／高清 60 帧，默认高清；立即生效并持久化，分别调整渲染分辨率、几何细节与反射成本。各档保留晃动和水位含义。
- 验证 0%、少量、半满、接近满、满水，持续倾斜、突然晃动及停止后的回稳。

### D. 录播与字幕

- 预览播放器采用圆角视频卡片；全屏时使用方形铺满。改用可裁剪的视频表面，删除旧原生按钮行，统一倍速、机位、双机位、全屏和截图操作。
- 手机学习页播放区固定在滚动顶部，减少浮层与滚动异步坐标的分离；位置变化合并处理，验证遮挡和横竖屏。
- 根据实际播放位置定位当前字幕并滚动；用户手动查看其他字幕时暂停跟随，提供“跟随播放”。支持选择全部或部分字幕用于提问。
- 截图通过原生播放器取得实际画面，携带课程、录播、时间和所选字幕进入提问；不截取应用外画面。

### E. 模型能力与全局助手

- 去掉可编辑的文件大小／上下文数字。先读取服务返回的模型能力与限制，缺失时采用明确的自动回退和按需能力验证，不仅凭模型名判断。
- 本地能提取文字的课件可走文字模型；图片／截图必须走可用的视觉接口。文件选择同时考虑本地解析能力、模型输入能力和设备资源限制，不把所有文件都声称为原生支持。
- 全局助手可查询课程／作业／资料目录，并按问题读取相关课程文件；默认不要求用户先选课程。后台只建立目录索引，不一次性上传全部课件。
- 当前课堂问题可附整段／选定字幕与截图；传输实际选择的内容，并保留来源和时间引用。取消、流式响应和错误恢复继续工作。

### F. Canvas 日程

官方 Calendar Events API 支持查询日期范围及课程／用户上下文。先实现只读日程查询与账号隔离缓存，只展示接口实际返回的课程事件；不能将日历接口等同于完整教务课表。

如有事件，展示今天／近期日程与上课提醒开关；没有事件显示简洁空状态。提醒沿用原生通知调度，并按账号清理、去重和更新。真实学校是否录入课程安排需用户账号环境验收，本轮不复用历史对话中的 Token。

### G. 验证、打包与文档

- 自动验证缓存命中／过期／并发去重／失败保留／跨账号隔离、目录按需读取、模型能力回退、选定字幕上下文、日程过滤和水位映射。
- 前端类型检查、测试、生产构建；Rust核心与新增接口的模拟测试；Android Kotlin／Rust构建。
- 浏览器检查 360／393 手机与 600／768／1280 Pad；Android 10 模拟器检查图标、选择面板、缓存恢复、播放器与传感器路径。实际视频／模型／学校日程没有真实验证时如实标记。
- 生成 0.5.0 预览 APK、校验值、截图、变更与验收记录，更新开源源码包。延续 D 盘工具链，不发布未经用户指定的 GitHub 远程仓库。
